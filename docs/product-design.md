# Tela 桌面版产品设计

> 版本：0.1（设计稿）
> 产品代号：Tela Desktop（中文暂称「Tela 桌面版」）
> 配套文档：[`api-proposal.md`](./api-proposal.md)、[`architecture.md`](./architecture.md)

---

## 1. 一句话

**把 Tela 的独立博客世界放到桌面上：安静、快、离线可读，中文英文都能读。**

---

## 2. 背景

### 2.1 我们看到的三个事实

1. **独立博客正在复苏，但读者回流很慢。**
   RSS 阅读器要么太重（Inoreader/Feedly 的信息流焦虑），要么太工具化（NetNewsWire 的纯列表）。
   Tela 的答案是"以人为主 + 编辑筛选 + 翻译"，这已经有 170 个博客、90 个每周活跃博客。

2. **语言是最大的墙。**
   一个中文读者面对英文、法文、德文、日文博客，通常只能放弃。Tela 的块级流式翻译是真正的差异点：
   它不是"整篇机翻"，而是原文与译文逐段对照，读起来像双语书。

3. **阅读应该发生在桌面上。**
   深度阅读需要大屏、键盘、专注、离线。浏览器标签页是被打断的地方；手机是碎片时间的地方。
   桌面应用可以做到"打开就有、翻页不卡、断网可读"。

### 2.2 现有产品的空位

| 产品 | 强项 | 空位 |
|---|---|---|
| Reeder | 设计、Apple 生态、流畅 | 无翻译、无社区、无发现目录 |
| NetNewsWire | 开源、轻、纯 RSS | 无翻译、无推荐、无设计投入 |
| Inoreader / Feedly | 功能全、团队 | 信息流过载、广告/付费墙、无独立博客气质 |
| Follow | 新一代、AI 摘要、社交 | 重、Web 优先、翻译不是核心 |
| Readwise Reader | 高亮/笔记、稍后读 | 不是 RSS 阅读器、订阅贵 |
| 微信读书/翻译工具 | 中文体验 | 不服务独立博客 |

**Tela Desktop 的空位**：唯一一个"独立博客 + 原生翻译 + 本地优先 + 桌面级阅读体验"的组合。

## 3. 目标用户

### Persona A：跨语言读者（核心）

- 28–40 岁，中文母语，英语可读但不轻松，对日本/法国文化感兴趣。
- 每天读 5–15 篇文章，习惯划线、收藏。
- 痛点：语言门槛、网页广告、阅读被打断、好文章找不到。
- 关键需求：**翻译要快、要对照、要能只读译文**。

### Persona B：独立博客重度读者

- 订阅 80–300 个源，用键盘，追求效率。
- 痛点：现有阅读器慢、同步冲突、离线差、排版丑。
- 关键需求：**快、稳、键盘全流程、离线完整**。

### Persona C：发现型读者

- 不订阅或订阅很少，喜欢"逛"。
- 痛点：不知道读什么；算法推荐同质化。
- 关键需求：**有品味的发现、能看到"谁在读/谁推荐"**。

### Persona D（次要）：独立博客作者

- 已在 Tela 认领博客，想看谁在读、谁推荐。
- 关键需求：**桌面端能看 dashboard、能回复推荐笔记**（P2）。

### Jobs to be done

| 场景 | 任务 | 成功标准 |
|---|---|---|
| 早晨咖啡 | 10 分钟看完昨晚的新文章 | 打开即见、未读清零、无卡顿 |
| 通勤/飞机 | 离线读完收藏 | 断网可读、进度同步 |
| 读到好句 | 划线 + 写一句笔记 | 3 秒内完成，之后能找到 |
| 遇到外文 | 一键对照阅读 | 首段译文 3 秒内出现 |
| 周末 | 找 3 个新博客 | Discover 有质量、可一键订阅 |
| 读到好文 | 推荐给关注者 | 带一句自己的话，出现在个人页 |

## 4. 产品原则

1. **安静优先。** 没有红点轰炸、没有"你有 1,283 条未读"的罪恶感。未读是信息，不是压力。
2. **本地优先。** 任何一次点击都不等网络。离线是常态，不是异常。
3. **翻译是阅读的一部分。** 不是工具栏里的一个按钮，而是正文的另一种呈现。
4. **以人为主。** 每篇文章背后有作者；推荐背后有推荐人；Discover 背后有编辑。
5. **克制的社交。** 点赞、推荐、关注即可；不做评论、不做私信、不做时间线成瘾设计。
6. **原生手感。** 键盘、菜单、快捷键、系统主题、通知、拖拽，都按平台习惯来。
7. **数据可带走。** 导出 OPML、导出高亮与笔记、退出即清空。

## 5. 功能范围

### 5.1 P0（MVP，v0.1–v0.3）

| 模块 | 功能 |
|---|---|
| 账号 | 设备授权登录（邀请制：先在浏览器加入再授权；服务端未就绪时用 Cookie 兼容）、退出、切换账号 |
| 订阅 | 按 URL 添加、OPML 导入/导出、文件夹、取消订阅 |
| 阅读 | 三栏布局、Unread/Today/Liked、已读/未读、全部已读 + 撤销 |
| 正文 | 块级渲染、图片、链接、代码、引用、表格 |
| 翻译 | 自动/手动、side/trans/orig、流式分块、失败与额度提示 |
| 收藏 | 点赞、推荐（带笔记）、高亮、笔记 |
| 搜索 | 本地标题/摘要 + 服务端补全 |
| 设置 | 阅读（字号/行宽/主题）、翻译、账号、缓存 |
| 同步 | 自动拉取/推送、离线队列、状态显示 |
| 系统 | 快捷键、命令面板、深浅色、窗口记忆 |

### 5.2 P1（v0.4–v0.6）

| 模块 | 功能 |
|---|---|
| 发现 | Discover 五个 tab（This week / Articles / Blogs / Readers / Blogrolls） |
| 社交 | 关注、Following 动态、他人资料页 |
| 博客卷 | 浏览、订阅全部、创建/编辑（简化） |
| 通知 | 新文章系统通知、Dock 徽标 |
| 多窗口 | 阅读窗口独立、分屏 |
| 导出 | 高亮/笔记导出 Markdown、全量数据导出 |
| 打磨 | 空状态、引导、动效、无障碍 |

### 5.3 P2（v0.7+）

| 模块 | 功能 |
|---|---|
| 作者 | 认领流程、dashboard、读者笔记 |
| 邀请 | 邀请码管理 |
| 资料 | 头像上传、昵称、简介 |
| 分享 | 生成引用卡片（本地渲染） |
| 朗读 | TTS（系统语音，无需服务端） |
| 扩展 | 脚本/插件（不做，除非有强需求） |

### 5.4 明确不做

- ❌ 自己抓取 RSS（一切以 Tela API 为准）
- ❌ 评论、私信、群组
- ❌ 算法推荐信息流
- ❌ 广告、付费墙、订阅制（至少第一年）
- ❌ 移动端（先把桌面做好）
- ❌ 全文服务端搜索（本地 + API 已够）
- ❌ 内容再分发/导出全文

```

设计要点：

- **侧边栏**：未读计数只用数字，不用红点；文件夹可折叠；订阅列表按未读数排序（可选）。
- **列表**：日期分组（今天/昨天/更早）；未读圆点；标题两行截断；来源 + 阅读时长；已读标题变灰。
- **阅读区**：标题（衬线大字）、作者/来源/时间、工具条、正文；工具条在滚动时吸顶。
- **状态栏**：同步状态、在线状态、翻译额度、未读总数——安静，不抢注意力。

三种模式：

| 模式 | 用途 | 布局 |
|---|---|---|
| **原文** | 我懂这门语言 | 单栏，最宽 640–760px |
| **对照** | 我在学语言 / 想核对 | 双栏，左原文右译文，块级对齐 |
| **译文** | 我只想读懂 | 单栏，译文优先；缺翻译时回退原文 |

翻译状态条（在工具条下方，仅外文文章显示）：

| 状态 | 显示 |
|---|---|
| 原文语言 = 阅读语言 | 不显示 |
| 未请求 | "Written in Japanese." + [翻译] |
| 请求中（首块未到） | "正在翻译…" + 骨架屏（3 行） |
| 流式到达 | "正在翻译… 8/24 段"，已到块淡入 |
| 完成 | "已翻译 · 简体中文" + [查看原文] |
| 部分失败 | "有 2 段未能翻译" + [重试] |
| 额度用完 | "今日翻译额度已用完，明天恢复。" + [读原文] |
| 博客选择不翻译 | "这个博客不提供翻译。"（不显示重试） |

### 7.5 高亮与笔记

```
选中文字 → 浮动工具条

│  ▍高亮   ✎ 笔记   ❝ 推荐   ⧉ 复制 │
└─────────────────────────────────┘

- 高亮默认用 `--color-highlight`（马克笔质感，不是方框）；
- 已有高亮：鼠标悬停显示笔记图标；点击打开右侧笔记面板；

- 高亮属于**原文或译文**（`side`），切换模式时仍然可见；
- 文章改版后，锚点自动重找；找不到时在笔记面板标"已脱离正文"。

### 7.9 离线与错误

| 场景 | 界面 |
|---|---|
| 断网（有缓存） | 状态栏"离线 · 2 分钟前同步"；列表正常；正文正常；写操作排队 |
| 断网（无缓存） | 文章位置显示"这篇还没有下载" + [重试]（联网后自动） |
| 同步失败 | 状态栏红色小点 + 悬停说明；不弹窗 |
| Token 失效 | 顶部横幅"登录已过期，请重新登录" + [登录] |
| 客户端过旧 | 对话框"需要更新" + [下载] / [稍后] |
| 服务端 5xx | 状态栏"服务暂时不可用，正在重试" |
| 翻译额度用完 | 翻译条提示，不阻断阅读 |

## 8. 交互细节

### 8.1 已读语义

与 Web 完全一致（ADR 0009）：

- 打开文章 → 已读（可关）；
- 每个订阅有"水位线"，新订阅时把历史标为已读；
- 30 天前的文章自动算已读；
- 手动"标为未读"优先于以上，直到再次阅读。

UI 细节：

- Unread 列表在一次访问中保留已打开的文章（避免列表跳动），离开后消失；
- "全部已读"是水位线操作，带 **Undo**（5 秒 toast）；Undo 之后逐条标未读（上限 200 条）；
- Liked 是"书架"，不显示未读开关。

### 8.2 键盘流

目标：**不碰鼠标读完 20 篇**。

```
j / k     下一条 / 上一条
Enter     打开
Space     翻页
m         标已读 / 未读
s         点赞
h         高亮选区（有选区时）
o         浏览器打开
l         复制链接
Esc       返回列表 / 关闭面板
⌘K        命令面板
⌘R        同步
1 / 2 / 3 原文 / 对照 / 译文
```

### 8.3 推荐

- 点击"推荐" → 弹出小面板：一句笔记（可选，≤500 字）+ [推荐]；
- 推荐后：按钮变为"已推荐"，可撤销；
- 推荐出现在个人页与关注者动态；
- 不显示"谁赞了"的实时流（克制）。

### 8.4 通知

- 新文章：默认关；开启后每 10 分钟聚合一次（"3 个博客更新了"）；
- 点击通知 → 打开对应文章；
- 不在应用内做"通知中心"；系统通知即可；
- Dock 徽标 = 未读数（可选，默认关）。

### 8.5 拖拽与多选（P2）

- 拖拽文章到文件夹 → 归档博客（不是归档文章）；
- `Shift+点击` 多选 → 批量已读/未读；
- 先不做，避免复杂化。

### 8.6 窗口

- 记住大小/位置/分栏宽度/最后打开的页面；
- `⌘W` 关闭窗口（macOS 不退出）；
- 支持全屏与分屏（macOS Split View / Windows Snap）；
- 双击标题栏缩放（平台习惯）。

## 9. 视觉设计

### 9.1 色彩（对齐 Tela Web）

| Token | Light | Dark |
|---|---|---|
| `paper`（背景） | `#F6F2EA` | `#1F1C18` |
| `surface`（卡片） | `#FFFFFF` | `#26221D` |
| `ink`（主文字） | `#1F1C18` | `#F6F2EA` |
| `body`（正文） | `#2A261F` | `#E6DFD2` |
| `ink-2`（次要） | `#5C554B` | `#CFC7B8` |
| `muted`（弱化） | `#766E62` | `#A39A8B` |
| `line`（分隔） | `#E3DCCF` | `#35302A` |
| `hover` | `#ECE6DA` | `#2E2A24` |
| `accent`（品牌绿） | `oklch(0.5 0.1 150)` | `oklch(0.74 0.12 150)` |
| `highlight` | `oklch(0.91 0.1 95)` | `oklch(0.5 0.09 90 / 0.55)` |
| `danger` | `oklch(0.5 0.15 25)` | `oklch(0.72 0.15 25)` |

使用规则：

- **纸感**：背景是暖白/暖黑，不是纯白/纯黑；
- **绿色只做强调**：链接、选中、品牌，不做大面积填充；
- **高亮像马克笔**：半透明、无边框、圆角 2px；
- **不用纯红/纯绿**做状态，用低饱和的 oklch。

### 9.2 字体

| 用途 | 字体 |
|---|---|
| 正文（拉丁） | EB Garamond（打包） |
| 正文（简中） | Songti SC / Noto Serif CJK SC / 思源宋体 |
| 正文（繁中） | Songti TC / Noto Serif CJK TC |
| UI（拉丁） | Figtree（打包） |
| UI（中文） | PingFang SC / Noto Sans CJK SC / 微软雅黑 |
| 代码 | SF Mono / Cascadia Code / DejaVu Sans Mono |

字号：

| 元素 | 字号 / 行高 |
|---|---|
| 正文 | 19.5px × scale / 1.55 |
| 中文正文 | 18px × scale / 1.8 |
| 对照原文 | 16px / 1.5（非 CJK），18.5px / 1.8（CJK） |
| 文章标题 | 32–36px / 1.25，衬线 |
| 列表标题 | 15px / 1.4 |
| UI | 13–14px |
| 元信息 | 12px，`muted` |

### 9.3 间距与形状

- 基础网格 **4px**；常用 8/12/16/24/32/48；
- 圆角：按钮 6px、卡片 10px、弹层 12px、头像 50%（或 9px 方形）；
- 边框：1px `line`；
- 阴影：菜单/弹层/对话框三级（对齐 Web 的 `shadow-menu/popover/dialog`）。

### 9.4 图标与动效

- 图标：Lucide（gpui-kit 默认资产），1.75px 描边；
- 动效：150–250ms，`ease-out`；只用于"出现/消失/选中"，不做装饰性动画；
- 减少动态：跟随系统 `reduce motion`。

### 9.5 密度

- 列表行高 72px（舒适）/ 56px（紧凑，可选）；
- 工具条 40px；
- 侧边栏项 32px；
- 阅读区左右留白：至少 48px（窄窗口 24px）。

## 10. 文案与本地化

### 10.1 语言

- 界面：简体中文、繁體中文、English、Français；
- 内容：原文 + 译文（四种阅读语言）；
- 语言切换不需要重启（与 Web 一致）。

### 10.2 语气

- **安静、具体、不责备**。
- 好："今日翻译额度已用完，明天恢复。" 不好："错误：配额超限 (429)。"
- 好："这个博客不提供翻译。" 不好："该内容不可翻译。"
- 空状态给下一步，不只说"没有内容"。

### 10.3 术语表

| 英文 | 简体 | 繁體 |
|---|---|---|
| blog | 博客 | 部落格 |
| subscription | 订阅 | 訂閱 |
| unread | 未读 | 未讀 |
| highlight | 高亮 | 劃線 |
| note | 笔记 | 筆記 |
| recommend | 推荐 | 推薦 |
| blogroll | 博客卷 | 部落格清單 |
| Discover | 发现 | 發現 |
| Following | 关注 | 追蹤 |
| translation | 翻译 | 翻譯 |

### 10.4 日期与数字

- 相对时间：刚刚 / 5 分钟前 / 2 小时前 / 昨天 / 3 天前 / 10月24日；
- 阅读时长：`10 分钟`；
- 数字千分位按 locale；
- 中文用全角标点，英文用半角。

## 11. 离线与同步体验

| 状态 | 表现 |
|---|---|
| 在线、已同步 | 状态栏"已同步 · 刚刚" |
| 同步中 | 状态栏小旋转图标，不遮挡内容 |
| 离线 | "离线 · 2 分钟前同步"；可读可写 |
| 有待发送变更 | "3 项更改待同步"（悬停看详情） |
| 冲突 | 不需要用户处理（LWW 自动）；极少数"被拒绝"给出 toast |
| 切换账号 | 提示"将切换到另一个账号的阅读列表" |

原则：**同步状态永远不打断阅读**。不用模态框，不用全屏 loading。

## 15. 待确认的产品问题

### 与作者

1. **品牌与命名**：叫 "Tela Desktop" 还是别的？图标能否复用 Tela 的 mark？需要书面许可吗？
2. **定位**：官方客户端、社区客户端，还是个人项目？这决定发布渠道与支持责任。
3. **邀请制**：桌面用户如何拿到邀请码？能否给桌面端一个专用码/白名单？
4. **翻译成本**：桌面端与 Web 共享每日额度吗？超出后桌面端是否可以有"自带 API Key"模式（不做默认）？
5. **社交范围**：桌面 v1 是否包含推荐/关注？还是先做"纯阅读器"？
6. **作者功能**：桌面是否需要 dashboard？还是引导到 Web？
7. **内容边界**：离线缓存上限、是否允许导出全文、是否允许"稍后读"式保存。
8. **数据与隐私**：崩溃上报是否接受？是否需要隐私政策页面？
9. **发布**：是否上架 Mac App Store？（沙盒、keyring、网络权限都会受影响）还是只做直接分发？
10. **支持**：出问题找谁？是否有 issue 仓库/社群？

### 内部

11. 首版是否支持"不登录先逛 Discover"？（建议支持）
12. 是否支持多账号同时登录？（建议 v1 后）
13. 高亮首版用"整段高亮"还是"文本选区"？（建议 M2 做选区，M1 可整段）
14. 是否内置 TTS？（建议 P2，用系统语音）
15. 是否做"阅读统计"（每周读了多少）？（建议不做，违背安静原则）

## 16. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 作者不开放 API/授权 | 项目无法合法分发 | 先做内部原型；尽早沟通；准备"只读公开内容"的降级形态 |
| 上游没有 LICENSE | 不能复制源码/设计资产 | 独立实现，只依据文档化契约；token/图标/文案逐一取得许可 |
| 协议变动 | 客户端失效 | `/client` 能力发现 + 自动更新 + 兼容层 |
| 翻译成本不可控 | 作者不愿开放 | 客户端严格复用配额；UI 透明显示；提供"仅原文"模式 |
| 桌面端工作量被低估 | 延期 | M0/M1 严格砍范围；先做"能读"再做"好读" |
| 跨平台差异 | Linux 体验差 | 优先 macOS + Windows；Linux 明确标注"社区支持" |
| 设计不像 Tela | 品牌割裂 | 复用 token/字体/图标；与 Web 并排走查 |
| 用户不愿再装一个阅读器 | 增长慢 | 主打"翻译 + 离线 + 桌面体验"的差异化；OPML 一键迁移 |
